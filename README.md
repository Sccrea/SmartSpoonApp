# EquiMeal · Jetpack Compose Android 应用 + Flask 数据服务器

按设计稿实现的移动端应用：**界面是 Jetpack Compose + Material 3**
（页面风格对齐 Gramophone：Material You 动态取色、大标题栏、MD3 列表行与底部导航），
**服务器只提供 JSON 数据接口**（网页端已废弃）。

| 项目 | 值 |
| --- | --- |
| 应用名 | **EquiMeal** |
| 包名 | `com.equimeal`（0.1.0 起；此前是 `com.smartspoon.l2` / 应用名「智味勺」） |
| 版本 | 0.1.0（versionCode 4） |
| 硬件 | 「**智味勺**」仍是那把 BLE 勺子的名字（广播名 / 设备列表），与上面的应用名是两回事 |

> **设计稿不在仓库里**（原始 PDF 约 7.8MB，逐页导出的 PNG 也在 `.gitignore` 里）。
> 设计稿下载：<https://wwbwa.lanzoue.com/iu9GU486xhva>
> 界面配色与间距都是自 1200×2134 的设计稿 PNG 逐像素取色的。

```
┌────────────────────────────┐         ┌──────────────────────────────┐
│  Android 应用（Kotlin 原生） │  HTTP   │  Flask 服务器（纯 JSON 接口）  │
│  · 启动时 GET /api/bootstrap│ ──────► │  · 菜品库落盘 data/dishes.json │
│  · 拍照识别 POST /api/recognize │ ◄── │  · 百度菜品识别               │
│  · 新增菜品 POST /api/dishes│         │  · 识别历史                   │
│                            │         └──────────────────────────────┘
│  · 蓝牙 BLE 连接「智味勺」    │  NUS    ┌──────────────────────────────┐
│    实时重量 / 口数 / 电量     │ ◄─────► │  勺子固件（Nano 33 BLE Sense） │
└────────────────────────────┘         └──────────────────────────────┘
```

> **真机勺子的对接协议见 [`docs/ble-protocol.md`](docs/ble-protocol.md)**：
> NUS 的 UUID、`S,/B,/A,/E` 帧格式、`ZERO/MODE/PING/VER?` 命令，以及现场排查清单。
> 勺子读数**只走蓝牙**：服务器不参与读数，也没有模拟设备（见下文「勺子数据只有一条来源」）。

## 运行

### 1. 启动数据服务器

```powershell
cd C:\Users\Administrator\Desktop\test
.\.venv\Scripts\python.exe run.py
```

默认监听 `0.0.0.0:5000`，启动时会打印本机与局域网地址。`HOST` / `PORT` 可覆盖。

### 2. 构建并安装应用

Gradle 由 wrapper 自带（`android/gradlew`，首次运行自动下载），签名用的 keystore 随仓库提交，
所以克隆下来只需要自备 **JDK 17** 与 **Android SDK**：

```powershell
# 前置：JDK 17（设好 JAVA_HOME）+ Android SDK
#       把 android\local.properties.example 复制成 local.properties 并填上 SDK 路径
cd android
Copy-Item local.properties.example local.properties   # 然后编辑 sdk.dir
$env:JAVA_HOME = "<你的 JDK 17 路径>"

.\gradlew.bat :app:assembleRelease     # 发布版（R8 压缩，~1.3MB）：app\build\outputs\apk\release\app-release.apk
.\gradlew.bat :app:assembleDebug       # 调试版（~16MB，带排查信息）：app\build\outputs\apk\debug\app-debug.apk

cd ..
.\.venv\Scripts\python.exe tools\smoke.py             # 服务器接口自检（不用先起服务器）

adb install -r android\app\build\outputs\apk\release\app-release.apk
```

> macOS / Linux 上把 `.\gradlew.bat` 换成 `./gradlew` 即可，其余一样。

详见 `android/README.md`（签名、长列表架构等）。

### 3. 在应用里指定服务器

应用默认连的是 **`https://sccrea64.cc.cd:16384`**（`State.DEFAULT_SERVER`，见 `Data.kt`）；
启动时会探测它以及用户保存过的地址，第一个 `/api/health` 通的就被采用，连上后读取菜品信息。
也可以在 **设置 → 杂项 → 服务器地址** 里「修改地址」或「重新读取菜品信息」。

> 换服务器只改 `Data.kt` 里那一个常量即可（`FALLBACK_SERVERS` 是同一批候选地址）。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 接口清单（JSON，不是网页） |
| GET | `/api/health` | 健康检查（含菜品数量） |
| GET | `/api/bootstrap` | **应用启动时读取**：菜品库 + 菜单 + 收藏夹 + 记录 + 统计 + 图表 + 设备 + 用户。带令牌时 `user` 是真实账号 |
| GET | `/api/dishes` | 菜品库 + 菜单 |
| POST | `/api/dishes` | 新增/更新一道菜 `{name, category, density, times}`，落盘保存 |
| POST | `/api/dishes/<id>/eat` | 记录一次食用（times +1） |
| DELETE | `/api/dishes/<id>` | 删除一道菜 |
| POST | `/api/recognize` | 上传图片识别菜品（`multipart/form-data` 字段 `image`，或 JSON `image_base64`） |
| GET | `/api/history` · POST `/api/history/clear` | 识别历史 |
| GET | `/uploads/<file>` | 查看上传过的图片 |
| POST | `/api/auth/register` | 注册 `{username, password, name?}` → `{user, token}`（用户名 2~20 位字母/数字/下划线/汉字，密码 6~64 位） |
| POST | `/api/auth/login` | 登录 `{username, password}` → `{user, token}` |
| GET | `/api/auth/me` | 用令牌取当前账号（App 启动时校验登录是否还有效） |
| POST | `/api/auth/logout` | 退出登录（只让这一个令牌失效，别的设备不受影响） |
| POST | `/api/auth/rename` | 改昵称 `{name}` |
| POST | `/api/auth/password` | 改密码 `{old, new}`（改完所有旧令牌失效，需要重新登录） |
| GET · POST | `/api/meals` | 当前账号的**用餐记录**（需令牌）。POST 上报本地记录并取回服务器合并后的完整列表 |
| GET · POST | `/api/usages` | 当前账号的**食用次数**（需令牌）。POST 是**覆盖**而不是累加 |

带令牌的请求用标准头：`Authorization: Bearer <token>`（调试时也支持 `?token=`）。

## 账号

**登录是可选的**：菜品库、菜单、用餐记录、收藏全在**本地 SQLite** 里，未登录也能完整使用。
登录之后，**用餐记录与食用次数改为按账号存在云端**（下面有归属表）。

### 数据归属（哪份数据存在哪）

| 数据 | 存在哪 | 说明 |
| --- | --- | --- |
| **用餐记录、每一口、食用次数** | **云端，按账号** | 未登录时只存本地；**登录时自动用云端覆盖本地** |
| 菜品库 | 服务器，**所有账号共用一份** | App 本地那份是离线缓存，列菜单时自动对齐 |
| 菜单、收藏、勺子名字、单位设置 | 本地 | 属于"这台设备怎么用" |

同步时机与方向（`AppCore.syncCloudData`）：

1. **登录成功后**、**App 启动（已登录时）**、**每次结束用餐后**都会对齐一次；
2. 方向是**先上报、再以云端为准覆盖本地**：
   - 用餐记录按「结束时刻」为 key 合并（两台设备各自离线吃的都不会丢），
     服务器把合并后的完整列表返回，App 用它**整体覆盖**本地 `meals`/`bites`；
   - 食用次数取云端的；本地明显更多（未登录期间吃出来的）就先上报覆盖云端；
3. **任何一步失败都不动本地** —— 网络不通、服务器是旧版没有这些接口时，
   宁可继续用本地那份，也不会把用户攒的记录清掉；
4. 退出登录前会先把本地这份推上去，避免"刚吃完就退出"丢掉记录。

服务器侧存储：`data/users.json` 里每个账号一个 `meal_records` 列表 + `usages` 字典
（与 `dishes.json` 同样"临时文件 + 原子替换"落盘）。上限 2000 条记录，超出时按时间留最近的。

| 关注点 | 做法 |
| --- | --- |
| 密码怎么存 | 服务器 `data/users.json` 里存 `pbkdf2_sha256$20万次$<随机盐>$<摘要>`；**绝不明文**，也不用可反查的单次 SHA |
| 密码比较 | `hmac.compare_digest` 常数时间比较，避免时序侧信道 |
| 登录态 | App 只存**令牌**（+ 昵称），**从不存密码**；令牌在服务器侧也只存 SHA-256 |
| 失败提示 | "用户名不存在"与"密码错误"返回**同一条提示**，不泄漏某个用户名是否已注册 |
| 数据隔离 | **一个账号一个库文件**：未登录用 `smartspoon.db`，登录后用 `smartspoon-<用户名>.db`。换账号 = 换库，不需要给每张表加 `user_id`（也就不会出现"忘写 where 就串数据"） |
| 退出登录 | 只清登录态并切回默认库；**不删**那个账号的库文件，下次登录数据还在 |
| 离线降级 | 令牌校验只有服务器**明确回 401** 才算失效；网络不通一律"先信本地"，不会一断网就把人踢出去 |

服务器侧账号库是 `data/users.json`（和 `dishes.json` 一样是 JSON：数据量小、能直接打开看、
部署环境没有数据库运维），写入走"临时文件 + 原子替换"，断电最多丢最后一次写。

自测：`python tools/test_accounts.py`（40 项断言，覆盖注册/登录/令牌/改昵称/改密码/落盘与重启，
用临时账号库，不污染 `data/users.json`）。

## 蓝牙（真机智味勺）

应用可以直接连**真实的勺子**，不再只依赖服务器模拟数据：

| 环节 | 实现 |
| --- | --- |
| 传输 | Nordic UART Service（NUS），勺子固件用 `BLEUart`，App 用原生 `BluetoothGatt` |
| 扫描 | 广播名 `SmartSpoon`；App **不做硬件级服务过滤**（广播包只有 31 字节，128 位 UUID 常放不下），改成自己按"服务 UUID 或名字像勺子"筛 |
| 数据 | 状态帧 `S,<重量×10>,<握持>,<稳定>,<<mark>>[,<电量>]`，100ms 一条 |
| 电量 | 连接弹窗里每台勺子都显示电量：**BLE 广播包里没有电量**，只有连上之后读标准电量服务（`0x180F` / `0x2A19`）才有 —— 所以从没连过的设备如实显示「电量未知」，连上过的显示最近一次读到的值（当前连着的用实时值） |
| 记口 | **由勺子发起**：按勺子上的 SW3 → 固件推 `B` 事件帧（带本轮舀取峰值重量）+ `mark` 递增，App 侧去重后自动累计；手机上不再有「记录一口」按钮 |
| 归零 | 「点击归零重量」= 手机侧清零 **+** 下发 `ZERO` 让固件重新 `tare()`（只做前者会被下一帧顶回来） |
| 断线 | 掉线后 1.5 秒自动按地址重连；连上但 3 秒没数据会明确提示"可能休眠/走远" |
| 权限 | Android 12+ 要 `BLUETOOTH_SCAN/CONNECT`（声明 `neverForLocation`，**不索取定位**）；11- 才需要定位。另有部分 ROM 要求**系统定位开关**打开，App 会主动检查并明确提示 |
| 蓝牙没开 | **用户点「扫描 / 重新扫描」或点某台勺子连接时**，若手机的蓝牙是关的，App 会调系统的「请求开启蓝牙」弹窗，用户点「允许」后**自动继续扫描/连接**（等蓝牙真的就绪，最多 3 秒）。**启动时的自动回连刻意不弹窗** —— 那是用户没做任何操作的时刻，不该被系统窗口打断；它只把"蓝牙未开启/缺权限"的原因写在界面上 |
| 连接成功提示 | 连上勺子在屏幕下方弹一句「智味勺已连接：xxx」。**启动时的自动回连也算** —— 那一步是静默发生的，不提示的话用户不知道到底连上没有 |
| 重新选择 | 在「连接智味勺」里点「重新选择」会**先断开当前勺子**再开始扫描：按这个按钮就是在表达"我不要现在这台了"，否则列表里旧那台还带着"已连接"的选中态，看起来像没生效 |
| 设备管理 | **两段式列表**：「设备范围」切到**已保存的智味勺** / **附近的智味勺**（切到"附近"会自动扫一次），下面「扫描附近的智味勺」「断开连接」按钮；点任意一行改名字，行上的「连接 / 断开连接」按钮真的连/断 GATT。**启动时自动回连上次的勺子**（固定行为，没有开关） |
| 用餐提醒 | 点一次「我已知晓」后自动关闭（落偏好），之后点「开始用餐」**直接进入用餐中**；开关在「设置 → **杂项** → 用餐流程」 |
| 列表排序 | 三个列表各有自己的排序（**维度下拉 + 正序/倒序**）：收藏食物、菜品列表是「字母顺序 / 收藏时间 / 食用次数 / 能量密度」；用餐记录是「用餐时间(序号) / 字母顺序 / 食用重量 / 食用热量」。收藏夹里的分类文件夹**固定按字母顺序**（不受维度与方向影响） |
| 用餐命名 | 用餐结果页第一行是「**本餐菜单**」：显示这一餐叫什么，**点一下可以改**（改名同时写回用餐记录）。用「使用现有菜单快速开始」时是那份菜单的名字，用「自定义本餐菜单」时是「自定义菜单」 |
| 热量换算 | 实时读数与记下的每一口都按**当前勺中食物**的能量密度算 —— 用餐中把勺中食物从黄瓜切成烤鸭，热量立刻按烤鸭算（以前用的是本餐第一道菜的密度，切了也不变） |

**勺子数据只有一条来源：真勺子。** 没连上就没有读数 —— 界面上如实显示"勺子未连接"。
（以前这里有两条退路：服务器模拟设备 `/api/device/*` 和 App 内的"模拟勺子"自测开关，
**都已删除**：它们会让界面上出现"看起来是真的、其实是编的"数值，用户无法分辨，记录也就不可信。）

**没连勺子时不能开始用餐**，流程上是这样拦住的：

| 位置 | 行为 |
| --- | --- |
| 自定义本餐菜单点「选好了」 / 点一份已有菜单 | 没连勺子时**直接打开"连接智味勺"的设备列表**（就是「重新选择」看到的那个界面），而不是停在一个写着"当前已连接：未连接"的确认页上 —— 那种页面除了再点一次「重新选择」无事可做 |
| 连接弹窗 | 没连勺子时按钮是「**先连接智味勺**」（点了回到扫描列表），只有 `SpoonLink.ready` 时才显示「开始用餐」 |
| `AppCore.startMeal()` | 兜底再检查一次：没连勺子就提示并送回连接列表，不会进入"用餐中" |

## 说明

- **菜品库是所有账号共用的一份**，存在服务器上（`data/dishes.json`）；App 本地那份是**离线缓存**。
  会在这些时机静默对齐：App 启动、**每次列菜单**（快速开始 / 自定义本餐菜单 / 菜单编辑 / 菜单管理）、
  登录之后。同步失败不打扰用户（离线是正常状态，照常用缓存），成功且有新菜时才刷新界面并提示。
  > **两套 id 不要混用**：服务器用字符串 `f13`/`f14`…，本地库 `dishes.id` 是 `INTEGER PRIMARY KEY`
  > （自动编号 1、2、3…）。凡是从服务器拿到的菜品要进界面/进本餐，必须**先落本地库再重读**
  > （见 `AppCore.saveDishToServer`）—— 直接把服务器的 `"f16"` 放进 `State.data.foods` 或
  > `State.selected`，会出现"加进来的菜过一会儿自己消失"，而且 `"f16"` 写进
  > `menu_items.dish_id`（INTEGER）会变成 **0**，整份菜单都指向不存在的菜。
- **菜单可以真的创建与修改**：设置 → 菜单里点某一份菜单（或底部的「＋」）会打开菜单编辑页，
  它用的是与「自定义本餐菜单」**同一份**选菜界面（搜索 / 分类 / 排序 / 拍照识别加菜 / 逐行勾选），
  差别只在顶部多了菜单名、底部把「选好了」换成「保存菜单」（编辑已有菜单时还有两步确认的「删除菜单」）。
  菜单可以只有一道菜，也可以随时改。
- 界面动效全部用系统能力实现：所有按钮都有**从按压点展开、裁进按钮形状的水波反馈**（类似
  Gramophone 播放/暂停按钮），弹窗是**系统原生圆角 Dialog**（平台自带的进出场动画）；
  页面加载不做弹出/淡入动画。详见 [`android/README.md`](android/README.md)。
- 设计稿的食物图是实拍照片，原生应用用 emoji + 圆角方块代替；头像为简笔画。
- 用餐中的实时数值：**来自蓝牙勺子**（100ms 一帧，勺子的 HX711/LSM6DS3），没有勺子时这一页会
  明确提示"收不到读数"。
- 「拍照识别菜品」识别出的新菜可以直接**保存到服务器菜品库**（`POST /api/dishes`），
  所有账号都能看到（下一次列菜单时自动同步下来）。
